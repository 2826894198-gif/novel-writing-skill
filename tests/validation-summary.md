# 验证说明

当前版本：0.4.0；更新日期：2026-10-15。以下保留历次验证的发生范围，不把旧证据追认为新功能验证。此说明不含原稿、人物名称、书名、私有链接或实际剧情表。

## 0.4.0 本轮验证

- 官方 quick_validate 通过；25个技能文件、50处本地相对链接、3个JSON模板完成结构/存在性/解析检查。选定作品身份词与本地绝对路径扫描无命中，另人工检查改动；这不是穷尽的隐私证明。
- 一名不继承主创聊天历史的执行者，收到两个中性新任务及技能入口，实际完成利益协商和温暖日常两段候选。它没有读取本轮长篇项目，没有联网和发布，没有把测试稿并入正式正文。
- 利益协商试跑完成了对方回应、主角让出有限宣传空间和双方确认可执行安排；已付款与未付款保持区分。主创复读认为对方最终接受原价仍较顺，现有交换虽提供解释，不能宣称冲突强度已充分改善。
- 温暖日常试跑保留了过去已做过同类活动的事实，完成当日小目标、双方主动回应与下一日约定，没有被冲突模块改成危机或复仇。
- 执行者实际修正一处物件表达和一处视角解释；两个任务只做局部核验，不虚构全章十一项、事实提交或用户终审。正文及实填报告留作品侧，未入库。
- 隔离限制：宿主工作区要求读取含其他书例子的根级写作规则，因此并非完全无外部故事片段暴露；执行者未采用这些专属例子。未做旧版同输入对照、真人盲读、实际 dots 加载或完整新书到交接的独立端到端测试。

结论：新增模块具备有限可执行证据，值得继续以实际章节和反馈迭代；不支持通过率、节省额度、长期一致性或收益提升的量化结论。通用脚本本轮没有修改；历史脚本测试不能充作新增创作能力的证据。

## 0.1.0 历史记录（2026-10-12）

## 已完成的协议检查

对照入口、参考与模板，模拟：旧章修改已有后章、新增普通细节、承诺已作但未履约、人物误信、提交中断、主创自审与用户终审分离、多作品不同风格、后章尚未写。

发现并修正默认 hash 口径不一致：统一无既有口径时采用整文件原始字节 SHA-256；保留已有项目口径及片段 hash 的明确边界，不跨口径比较。

这些是审读和情境推演，不是数据库事务、网络中断或自动恢复的故障注入测试。

## 实际写作试跑

输入为两部已有连续正文的作品，分别续写一章；两部采用不同阅读承诺。保留初稿，主创自检后独立对照相关前文审读，进行局部修改及回查。

实际发现并修正：
- 对话中食材信息未交代却被另一端人物特指：补合理的信息来源
- 连续动作中缺少从厨房返回餐桌的过渡：补最小承接
- 场景中的凳子位置前后不一、接电话动作欠自然：在初稿自检中修正
- 相邻章重复相同问笑节拍：压缩重复对白，保留新场景功能
- 回忆年龄措辞可能暗示角色经历了设定之外的年份：改为准确时点

保留有意义的复杂性：未强制人物立刻成熟，未把新增普通回忆一律判错，未因重复词出现就机械删除。

## 试跑引发的技能微调

两章写前计划与实际正文有偏差。原计划不应覆盖已发生事件。增加“写后执行差异”字段，要求候选增量依据实际正文；用一次已发生告知、一次未采用的称呼设想复核，并检查无差异场景可以正常标无变化，不强造差异。

## 尚未证明

- 长篇多批次稳定性、跨卷大修完整性与真实故障恢复
- 用户对这两章阅读体验的终审认可
- 平台规则符合性、审核通过、公开发布或收入增长
- 具体模型费用或额度节省比例

没有将测试稿提交到小说平台，也未将正文存入本仓库。后续验证以实际获授权的创作批次和具体缺陷继续，不用扩写数量冒充可靠性。
