# 事实、时间与采纳

本文件的字段是自定义工作协议，不是任何软件的API。条目模板见 [fact-entry.json](../assets/templates/fact-entry.json)。

## 四个独立问题

- **这是什么**：fact（发生事实）、belief（人物误信）、inference（编辑归纳）、plan（未来方案）、unresolved（待确认）
- **当前是否采纳**：candidate / accepted / rejected / superseded。文件名有“事实”不代表内容已采纳
- **什么时候成立**：effective_from / effective_until 使用故事时间或场景位置，可为相对时间。不要用文档更新时间代替故事时间
- **谁什么时候知道**：known_by 逐人记录 learned_at、获知方式、来源及确信程度。客观事实、读者所知、视角人物所知分别判断

`current` 是在“目标故事时间＋选定有效版本”下成立的已采纳事实视图，不是删去历史后的最新摘要。`plan` 单独保存且标提出者、状态与依据；计划写入大纲不表示事件发生。回忆和非线性叙事必须同时考虑故事发生位置与正文揭示位置。

## 来源与证据

每条有效事实附书籍、章/场景、版本/hash、原文定位及短证据或明确用户设定来源。人物性格归纳保留为归纳；多处正文可以加强判断，不能据此冒称旧正式人设。信息缺失用null并说明缺口；空数组不作为“确认没有”的证据。

新稿中实际写出的事件先入候选增量；经该章正文及delta验收、项目采纳门禁与提交一致性核验后才更新current，详见 [持续运行](operations.md)。取消或退回候选时，连带撤销依赖它的临时推论，不污染已采纳记录。未来章若依赖未采纳候选，明确这一前提，不当作旧正典。

## 变化账

- 关系：记录行为进展与明确称谓分别成立的证据；亲近不自动等于正式关系
- 物件：持有者、所在位置、转交/归还场景；相似物件要有不同身份
- 钱：标现金、卡余额、报价、应付、实收口径；未知开支不能推算精确余额
- 约定：提出、接受、变更、兑现、取消分别记录，注明谁向谁、何时、条件；已经同意是发生事实，未来履约另记待兑现目标；愿望不等于共同承诺
- 能力/信息：来源、适用条件、限制和已验证范围；经验不自动变成全知

## 修改既有事实

1. 并列冲突证据，判断笔误、误信、刻意隐瞒还是设定变更；不要临时编“记错了”替作者错误解围
2. 提出最小修复，定位依赖该事实的前后章、摘要、知情条目和约定
3. 授权内修正；重大改设定需要决定时停在方案。保留原记录及替代关系，不静默覆盖
4. 重算修改章节hash，回看影响链中实际存在的章节，记录修改与无需修改的理由
5. 更新候选记录并重新验收；满足采纳条件后原子式更新有效索引和事实视图，不让新摘要搭配旧正文
