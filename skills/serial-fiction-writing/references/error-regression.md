# 按缺陷触发的回归

只在发现具体缺陷、复现同类问题或整理经验时调用。项目侧记录实际正文及证据；通用skill不接收实填记录。复用已有审查定位，不再平行抄一套事实库。

## 先判原因，再补检查

已有SC01覆盖时间、SC02/SC05覆盖承接与物件、SC07覆盖指代与搭配。已有检查标“通过”但错句仍在，是执行或证据覆盖遗漏；不能宣称原来没有规则。先把遗漏变成可复核动作，只在现有方法确实不能覆盖时增补规则。哈希证明检查对象，不证明检查已做对。

以下按本次缺陷选用，不要求每章全填：

- 数量化时间：触发为相隔天数、周数或倒计时 → 找起讫事件、日期及计数口径，算结果并逐句比对 → 改错句和受影响依赖 → 回查起点、终点与已有后章的相关跨度 → 人物刻意误报须有叙事依据；日期不明时不假造精度
- 旧场景回忆或旧物再现：触发为“记得”、姿势、位置、持有人或跨场景转移 → 回读发生处，分清已写事实与新细节；后者是否暗含未经建立的旧事实 → 改成有依据的回忆、在授权内交代必要转移，或避免依赖未知轨迹 → 回查来源场景和同物件后续 → 不要求所有日常新物件都有旧章来源，不为圆错编失忆
- 转述与多人同场：触发为换主语、间接引语、动作连写 → 逐句确认谁说、谁做、谁得知，能否误读为另一人 → 仅在歧义处补姓名或调整分句 → 连读相邻句并核人物知情 → 主语明确时不机械重复姓名
- 动作与感受搭配：触发为读来别扭或反馈指向具体词组 → 在完整句境中核动作、身体感受和角色声线 → 最小替词 → 连读该段并确认未改事件因果 → 方言、人物口癖或有意陌生化不是自动错误
- 恢复状态冲突：触发为旧记录待办与当前索引不同 → 按 [持续运行](operations.md) 核同hash、依赖、实际审查和完整提交 → 更新当前摘要的替代引用，保留历史 → 验证可以从当前入口恢复且未冒称外部同步 → 缺证据仍待查，不以最新日期定真伪

## 项目条目与频率口径

最小条目：触发 → 来源/版本与可定位证据 → 原因（缺规则／漏执行／证据不足／待查）→ 最小修复 → 实际回归与剩余边界。已有项目记录够用就引用；没有必要另建文件。

同一错句在多个候选版本、多个报告中出现只计一次。一次高后果错误可保留针对性检查，但不称高频；两个不同事件可支持“本次样本同类重复”，不证明长期发生率。列清观察范围与实例，不用虚构百分比证明有效。修复后仍需在后续真实触发时观察是否漏检，不声称新规则保证不复发。

## 中性回归小样（方法演练，非作品效果证明）

- 起点2030-04-02、终点2030-04-16，普通日期差14天；“过去十天”应查错。若说“含首尾第十五天”，应核口径而非强改为14
- 原场景坐在木箱上，回忆写站在门边：须查冲突。当前新场景站在门边不因旧场景坐着而报错
- 包原留旅店，回家直接从该包取物：须核转移。新写家中普通水杯不自动要求补购买史
- 一人练习、另一人听转述：先标清两种动作的主体；单人连续动作无需每句加姓名
- 历史候选写待查，当前同hash审查覆盖且提交完整：引用完成依据；只有同hash而无实际审查不能放行

这些小样只限定检查动作及边界；日期运算可机械验证，其余判断仍要回读正文。
