# 项目接入：六层够用底座

只收集能改变当前写作决定的信息。已有资料足够时接入索引，不重建百科，不强行填满未知项。

1. **作品承诺**：题材、读者将获得的体验、当前阶段问题、已定创作边界。读者画像和市场效果若无数据，只能标编辑假设。
2. **人物与关系**：当前愿望、长期牵挂、惯性弱点、说话/做事特征、不同关系下的差异、已发生证据、可能促成变化的经历。一次动作不直接归纳成终身性格；配角有自己的事务与选择。
3. **世界与时间**：绝对或相对日历、时代和职业限制、地点及交通、物件与资金。未确定的日期不要擅自精确化；现实技术或专业知识不确定且影响剧情时，核验可靠来源或保留不确定。
4. **剧情与约定**：逐章实际变化、未解问题、承诺状态、伏笔依赖、未来方案。普通细节不必都升格为伏笔。
5. **本书表达**：视角、叙事距离、信息投放、对白特点、轻重节奏、重复风险、语言和标点约定。记录实际采用的词形、称谓与特殊文本格式，服务交接一致性。
6. **验收与版本**：正文身份、基准、候选、有效版本、审查证据、事实采纳标准、输出状态。

## 最小项目入口

入口应指向：有效版本索引、分书风格卡、人物登记、事实/时间线、约定登记、候选区、审查记录。模板不是必须采用的新目录；保留用户现有组织方式。

索引列明 book_id、chapter_id、版本、文件位置、校验值SHA-256及口径、采纳状态、最后核验时间。以当前文件重新计算验证，不从“最终版”等文件名推断已通过。

若项目已有hash口径，严格沿用并记录；若没有，默认计算整文件原始字节的SHA-256，包含标题、换行与全部空白，不做Unicode或换行规范化。若另算正文片段hash，须明确剔除边界，使用不同字段保存；不同口径的值不得直接比较。不要悄悄改变计算方式。无法计算时明确未验证，不编造数值或版本一致结论。

## 权限与取舍

明确本次可改章节、是否可续写、是否可改变已发生事实及重大走向。作者在授权内决定表达取舍，审阅者提供证据；只审任务不改正文。新用户决定如涉及改设定，记决定依据与影响范围。单次试验有效不自动变成永久规则。

采纳标准由项目定义，例如作者接受或明确授权的主创验收。标准不明时维持候选，不把“用户批准写作方法”解释为“自动批准每个情节”。
