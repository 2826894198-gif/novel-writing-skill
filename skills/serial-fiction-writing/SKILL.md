# 长篇逐章写作

扩展试行版。把作品自己的阅读承诺、人物选择和已发生事实接成可核验流程；登记服务创作。验证范围与来源见 [sources.md](sources.md)。

## 先定当前状态与授权

明确作品、获准章节、续写或修订、输出位置和采纳决策人，保留旧交付。先核有效正文索引、分书风格和事实依赖；摘要只作索引，关键承接回读正文。当前状态以正文hash匹配的完成审查、有效采纳与完整提交为依据，不靠文件名或最新日期猜测；历史快照不覆盖有证据的当前状态。

用户明确授权主创采纳并连续写作时，在该范围内逐章验收、采纳和继续，不默认逐章等待用户批准。仅批准方法不等于授权全部剧情；重大未授权变更或硬项阻塞只暂停受影响部分。项目采纳、用户终审、平台保存/审核和发布分别记录。

## 按本次阶段调用

不要每章读取全部资料。相关规则已读且未变时，只载入本章依赖及变化；以下各项给出调用、产出与检验。

- 首次接入或底座缺失：读 [项目接入](references/project-context.md) → 建有效索引及最小底座 → 核来源、hash口径和权限；不重建已有资料
- 新阶段、节点结束或反复停滞：读 [阶段与追读](references/stage-and-reader-promise.md) → 一张简短阶段卡 → 核具体期待、真实变化和题材承诺；日常小修跳过
- 重要人物选择、成长或关系变化：读 [人物与关系](references/character-and-relationship.md) → 在原档案补必要变化 → 核选择、双方回应与证据；不另建平行人物库
- 每章写前：用 [事实与状态](references/continuity.md) 与 [场景与风格](references/scene-and-style.md) → 轻量场景卡 → 核前章后果、角色知情与约定，只加载相关资料
- 每章写后及改后：执行 [验收与修订](references/review-and-revision.md) → 同hash审查与事实delta → 11项证据、硬错修复、相关旧章回归；未知后章只记待验证
- 采纳、恢复、设定变更或批次收尾：读 [持续运行](references/operations.md) → 一致提交与当前状态记录 → 核正文、索引、账本和未完事项
- 有实际反馈或要比较写法：读 [反馈与验证](references/reader-feedback.md) → 定位到版本的最小修改试验 → 区分编辑判断、AI模拟、真人反馈与平台数据，不以自评分证明收益

## 一章闭环与边界

候选正文 → 实际执行差异与候选delta → 同版本验收 → 授权范围内采纳 → 正文/索引/账本一致提交 → 下一章。没有具体缺陷不反复重写；批量目标不免除逐章闭环。

交付净稿与短记录：结论、检查范围、实际修改、剩余问题和承接。没有通过硬项的稿件标待修；没有下一章，不声称全上下文已核验。

事实、误信/推断、未来计划与待确认分开，候选与采纳分开，发生时间与得知时间分开。有证据的当前事实优先于设计和提纲；旧事实若有错仍须核证修正。风格按书维护，不设全书通用对白比例、悬念配额或AI检测门槛。

通用skill只含原创方法、公开来源和空白模板；正文、实际书名人名、实填剧情、私有链接和授权记录留项目侧。本skill不安装工具、连接账号、上传或发布；外部动作须另有明确授权。
